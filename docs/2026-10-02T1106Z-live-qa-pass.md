## Visual triage

Findings returned by the reviewer, and what happens to each. The rule is the one
in `docs/qa-checklist.md` § 4: keep it only if it is visible in the PNG, breaks
a stated rule in `DESIGN.md` / `UX_FRAMEWORK.md`, and is reproducible. Most of
this batch is the model's own taste and is discarded.

**Discarded — the reviewer contradicting itself or the rubric.** Seven of the
findings claim grotesk text "should be editorial serif": the header wordmark, the
nav links, the section title, body copy, product names, badges and accordion
titles. `DESIGN.md` says the opposite — grotesk is the UI face and serif is
reserved for display. A grader cannot flag "uses the grotesk" and "should use
serif" in the same run without one of them being wrong; the rubric's own line
"at most two type families: editorial serif for display, grotesk for UI" settles
it. Not defects.

Also discarded: "cart shows 0 items" (an empty cart is the correct initial
state), en-dash-vs-hyphen typography, orphan-line preferences (present on both
pages, so if it mattered it would be the house line-height, which is unchanged
and out of scope here), "button text not centred" asserted on the same button at
820px that it calls correctly centred at 390px, and two claims about
`border-radius` that contradict the rubric — it asks for **0–2px**, so a 0px
button is compliant and asserting otherwise inverts the rule. HARD RULE 8 rejects
non-zero radius, not zero radius; the `radius-gate` check on `0149caa` is green.

## Method notes worth keeping

**The pooled vision route failing open is the STI-226 failure mode wearing an
infra costume.** `REVIEW FAILED: HTTP Error 403` prints once per capture and the
run's exit code is `1` — correct. But the six PNGs are on disk and look like
evidence, and a later reader who does not know the grader never spoke will see
six screenshots and infer a completed visual gate. The summary line
(`6 capture(s), 6 failure(s)`) is the only thing standing between that and a
false green, which is why this pass records the pinned model and its 200 in the
doc instead of trusting the skill to stay fixed. Same shape as the
"`tokens-in: 0` with HTTP 200" note already in this runbook.

**One model in the pool was free, not broken.** With `auto/best-vision` 403ing,
the cheap move is to report "reviewer leg down, visual gate unverified" — which
is what the previous two passes did. The blocker was one *route* inside a pool,
and `google/gemini-2.5-flash` accepted the identical bytes. Probing two or three
sibling model ids against the *real* screenshot (not a 1×1 toy, per the
[STI-575](/issues/STI-575) lesson already recorded above) takes about a minute
and converts a permanently unverified gate into a green one. Probe the pool
before declaring the pool down.

**`--model` is a flag, so pinning it is not a fork.** The skill's
`DEFAULT_MODEL = "auto/best-vision"` is still the default for everyone else. The
fix that belongs in the skill is a fallback list like the one the
2026-09-27 note says it used to have; that is an infra change and is not mine
to make from a QA heartbeat.
